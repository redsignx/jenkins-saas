# 常见问题（FAQ）

本文档收录了各团队关于 Jenkins Build Service 内部计费的常见问题。

---

## 计费规则类

### Q1：失败的构建也要收费吗？

**是的，失败构建（`FAILURE`、`UNSTABLE`）按实际运行时长收费。**

原因：失败构建同样占用了 EC2 实例或 Mac Mini 资源。平台无法区分"有价值的失败（如测试失败）"和"无效的失败（如配置错误）"，统一按实际资源消耗计费是最公平的方案。

**例外**：如果构建在 Agent 分配之前被中止（`ABORTED`，状态为"在队列中取消"），则**不收费**，因为此时没有实际分配任何资源。

💡 **建议**：减少失败构建率不仅能节省费用，也能提升团队效率。参考 Dashboard 中的"构建失败分析"面板。

---

### Q2：构建排队等待的时间算不算钱？

**不算。** 排队等待时间（Queue Time）不计入账单。

计费从 Agent 开始执行构建时开始，到构建结束时结束。排队等待时间仅记录在系统中，用于 SLA 监控和平台容量分析，不影响费用。

---

### Q3：计费精度是多少？是按秒还是按分钟？

**按分钟计费，向上取整（ceil）。最小计费单位为 1 分钟。**

示例：
- 构建运行 30 秒 → 计费 1 分钟
- 构建运行 1 分 1 秒 → 计费 2 分钟
- 构建运行 10 分 0 秒 → 计费 10 分钟

底层数据以**秒**为精度采集，月末聚合时按分钟计算。

---

### Q4：Pipeline 中的并行 Stage 如何计费？

**取决于并行 Stage 是否使用了多个 Agent：**

- **同一 Agent 上的并行 Stage**：整个构建只算一次，按总运行时长计费
- **分配到不同 Agent 的并行 Stage**：每个 Agent 单独计费，然后**加总**

示例：
```groovy
parallel {
    stage('Android') { agent { label 'ec2-linux-medium' } ... }  // 10 min
    stage('iOS') { agent { label 'mac-mini-ios-m2' } ... }       // 15 min
}
// 计费：10 min EC2 + 15 min Mac Mini
```

---

### Q5：跨月的构建怎么计费？（比如深夜开始、次日结束的构建）

跨月构建按**构建开始时间**所在的月份计费，全部费用归属该月。

示例：
- 构建开始时间：1月31日 23:50
- 构建结束时间：2月1日 00:20（运行30分钟）
- 计费归属：**1月账单**，计费 30 分钟

---

### Q6：Artifact 存储是怎么计算的？

Artifact 存储按**月末 S3 存储量（GB）**计费：

1. 每天 23:59 拍摄一次 S3 存储快照
2. 月末取当月**平均存储量**计费（非最大值，对团队更公平）
3. 超出 Tier 配额的部分按 $0.025/GB/月 计费
4. 默认保留 90 天，超过 90 天的 Artifact 自动删除（可申请延长）

---

### Q7：如果我在 Mac Mini 上跑了非 iOS 的构建，会按什么价格计费？

按 **Mac Mini 单价**计费（更贵），而不是 EC2 单价。

**强烈建议**：只在 Mac Mini 上运行需要 macOS 的 iOS 构建。
Android、服务端等构建请使用 EC2 节点（费用低 7-10 倍）。

可以通过在 Jenkinsfile 中明确指定 Agent Label 来避免误用：
```groovy
agent { label 'ec2-linux-medium' }  // Android 构建，使用 EC2
agent { label 'mac-mini-ios-m2' }   // iOS 构建，使用 Mac Mini
```

## Tier 选择类

### Q8：我应该选哪个 Tier？

使用以下决策参考（基于每月用量）：

| 你的情况 | 推荐 Tier |
|---------|---------|
| 小团队（<5人），偶尔构建，无 iOS | Tier 1 Basic |
| 中型团队，日常 Android + iOS 双端 | Tier 2 Standard |
| 大型团队，高频构建，Release-critical | Tier 3 Premium |
| 月 EC2 < 400 min，Mac < 80 min | Tier 1 Basic |
| 月 EC2 400-1,600 min，Mac 80-400 min | Tier 2 Standard |
| 月 EC2 > 1,600 min，Mac > 400 min | Tier 3 Premium |

**最准确的方法**：查看 Billing Portal 中的 Tier 推荐工具，输入历史用量，自动推荐最优 Tier。

---

### Q9：我选了 Tier 2，但某个月因为大版本发布，用量暴增，怎么办？

超出配额的部分会自动按**超额单价**计费，不会强制中断构建。

对于大版本发布前的临时需求：
1. **提前申请临时 Tier 升级**：发布前 1 周申请，仅限当月有效，当月按新 Tier 计费
2. **购买一次性 Build Credit**：向平台购买额外的 Build Minutes，按块计费

如果连续 3 个月都出现超额 > 50%，建议正式升级 Tier。

---

### Q10：Tier 降级有什么限制？

降级申请需满足以下条件：
1. 连续 3 个月实际用量 < 配额 40%
2. 提前 1 个月申请
3. 降级后 3 个月内不可再次降级（冷却期）

降级生效后，原有更高 Tier 的所有权益（SLA、优先级等）随即失效。

---

### Q11：年付有什么好处？如果中途团队解散了怎么处理？

**年付优惠**：
- Tier 1：9折（年节省 $600）
- Tier 2：9折（年节省 $2,160）
- Tier 3：8.5折（年节省 $9,000）

**中途退订政策**：
- 年付费用**不退款**，但可以转换为 **Build Credit**
- Build Credit 可在年内抵扣超额费用
- Build Credit 也可转让给同部门其他团队（需 Manager 审批）

---

## 超额处理类

### Q12：超额之后构建会被强制停止吗？

**不会强制停止**，但超额部分会产生额外费用。

超额行为（Overage）触发以下动作：
1. 达到配额 100% 时：发送告警邮件 + Slack 通知
2. 超额 > 50%（即用量 > 配额 150%）时：系统推荐升级 Tier
3. 超额 > 100%（即用量 > 配额 200%）时：**仅 Tier 1 团队**会触发并发限制（最多 1 个并发，而非 2 个），以防止单个团队影响全局

Tier 2、Tier 3 团队超额后不限制并发，仅按量计费。

---

### Q13：如果我的团队本月临时超额很多，但原因是平台故障导致构建反复失败，这部分费用可以免除吗？

**可以申请免除。**

如果超额的原因是**平台原因**导致（如：
- Jenkins Controller 不稳定导致构建频繁重排队并重试
- EC2 Agent 节点问题导致构建被错误终止并重跑
- 平台配置错误导致大量意外构建触发

则可以通过争议处理流程提出申请，平台团队会核查相关时间段的系统日志，如确认是平台责任，相应费用会从账单中扣除。

申请入口：Billing Portal → "对账单有异议"

## 账单和争议类

### Q14：我认为账单上某些构建记录不属于我们团队，应该怎么办？

提交争议时，请提供：
1. 具体的 Build URL 或 Build Number
2. 该构建实际应归属的团队（如果知道的话）
3. 你认为不属于本团队的理由

可能的原因：
- Jenkins Folder 权限配置错误，其他团队的 Job 放在了你的 Folder 下
- Pipeline 中 `TEAM_ID` 环境变量配置错误

平台团队会根据 Jenkins 日志（包括谁触发了该构建）进行核查，并调整账单。

---

### Q15：账单有错误，我需要多久内提出？

**账单发出后 5 个工作日内**需提出争议。

- 账单发出日：每月 5 日
- 争议截止日：每月 12 日
- 争议处理完成：每月 15 日前
- 财务转账：每月 15-20 日

逾期未提出争议的，视为对账单确认，不再受理追溯申请。

**特殊情况**：如确有充分理由（如账单发出时相关人员不在岗），可申请延期，由平台团队 Manager 酌情处理。

---

### Q16：我能看到其他团队的费用和用量吗？

**不能。** 每个团队只能看到自己团队的用量和费用。

**例外**：
- 同部门的 Director 级别以上管理者可以申请查看其管辖团队的汇总报告（需提交申请）
- 平台团队可以查看全局数据，用于平台容量规划
- 财务部门可以查看全公司汇总数据，用于内部转账

---

### Q17：我们团队有多个 Jenkins Folder（子项目），账单是分别的还是合并的？

**默认按顶层 Folder 合并**。

例如：
- `mobile-android-team/app-a/main`
- `mobile-android-team/app-b/feature`

以上两个 Job 都归属于 `mobile-android-team`，统一计入同一账单。

如需按**子项目分拆账单**（如 App A 和 App B 分别属于不同 Cost Center），需：
1. 在 Jenkins 中将不同项目放到不同的顶层 Folder
2. 向平台团队申请分拆账单配置
3. 财务部门提供对应的 Cost Center 代码

---

### Q18：我的团队刚加入，还没有 Cost Center，能先开始用吗？

**可以先开始用，但必须在 30 天内完成 Cost Center 映射。**

对于尚未配置 Cost Center 的新团队：
- 前 30 天：免费试用（Tier 1 Standard 配额）
- 第 30 天前：完成 Cost Center 申请和 Tier 选择
- 第 31 天起：正式计费开始

如果超过 30 天未完成配置，该团队的并发构建数会被限制到 1（以提醒完成配置），但不会停止服务。

## 技术和操作类

### Q19：如何知道我的构建用的是哪种 Agent（EC2 还是 Mac Mini）？

有以下几种方式：

1. **在 Jenkinsfile 中打印 Agent 信息**：
   ```groovy
   stage('Build') {
       agent { label 'ec2-linux-medium' }
       steps {
           echo "Running on: ${env.NODE_NAME}, Labels: ${env.NODE_LABELS}"
       }
   }
   ```

2. **在 Jenkins UI 中查看**：构建详情页 → "在节点 XXX 上运行"

3. **在 Billing Dashboard 中查看**：每次构建记录包含节点类型信息

### Q20：我想降低费用，有哪些方法？

以下方法可以显著降低构建费用：

| 方法 | 预计节省 | 难度 |
|------|---------|------|
| 启用 Gradle/Maven 远程缓存 | 20-50% 构建时间 | 低 |
| 使用更小的 Agent 规格（如 small 而非 medium）| 40% 单价 | 低 |
| 减少 FAILURE 构建（优化 Pipeline 稳定性）| 10-20% 费用 | 中 |
| 将 Android 构建从 Mac Mini 迁移到 EC2 | 70-85% 单价 | 低 |
| 减少不必要的 Cron 触发（如非工作时间无用触发）| 变量 | 低 |
| 启用构建条件（只在代码变化时触发）| 20-40% 构建次数 | 中 |
| 将单体 Job 拆分为增量构建 | 30-60% 构建时间 | 高 |

详细优化指南请参考：[构建优化最佳实践文档]（待补充）
